# Agent Note: 聊天回合归属与明确的本地访问授权

Status: implemented

## 问题

聊天消息能够对本地工作区运行工具，并把输出发回群聊。不明确的发送者策略会暴露本地能力；从整个 agent 空闲区间选择最后一个回答，可能把其他来源的回答发给该群。远程命令还需要中断那些必须等待本地审批才能继续的任务。

## 决定

桥接要求发送者白名单或显式允许所有人的选择。群消息通过准确的机器人提及验证。已接受的聊天共享配置的工作区，隔离由独立宿主提供。指定或宿主默认的 agent preset 提供工具，宿主权限策略始终有效。

每个聊天都有容量受限的队列和一个会话绑定。提交的 dsh 用户消息 ID 在持久日志中标识所属回合。回复提取在该回合结束时停止，取消或失败优先于部分文本。即时控制命令无需排在任务之后，即可查看、取消、清空或重置桥接任务。

插件卸载负责异步清理，停止接收消息、取消任务、等待会话释放，并通过 stdin EOF 请求事件消费者取消订阅。去重记录保存在有容量上限的内存中，只能跨同一插件实例内的消费者重启保留。

## 考虑过的替代方案

**默认不限制访问。** 应用可见范围和聊天成员可能包括不应获准使用本地工具的人。强制指定发送者策略，使这一信任选择明确。

**等待整个 agent 空闲后取最后一个回答。** 同一 agent 可以接收其他来源的任务。即使这些来源的回合交错，按消息 ID 关联也能保留回复归属。

**控制命令排队。** 位于等待审批任务之后的命令无法停止该任务。控制命令绕过普通任务队列，但保留相同的访问检查。

**强杀消费者。** CLI 可能需要注销服务端订阅。正常关闭能保留该清理机会，代价是等待无响应的子进程。

## 后果

桥接能准确关联任务与回复，并限制待处理任务数量。它仍然是面向可信用户的集成：聊天隔离不隔离文件，群回复对群成员可见，投递不保证恰好一次。插件重启会丢失待处理任务和聊天绑定。真实租户权限与网络投递需要在合成回归测试之外，单独完成经授权的冒烟验证。
