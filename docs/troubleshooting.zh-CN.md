# 故障排查

[English](troubleshooting.md) | 简体中文

从下面的现象开始排查。公开日志中不要包含凭据和消息内容；报告可复现问题时请附上插件、dsh、Node.js 和 `lark-cli` 版本。

| 现象 | 检查与处理 |
|---|---|
| 启动提示发送者列表为空 | 在 `allowedSenders` 中填写当前应用下的 `open_id`，不要仅为绕过检查而扩大访问范围。 |
| 找不到 `lark-cli` | 在启动 dsh 的同一环境中运行 `lark-cli --version`，或把 `larkCliPath` 设置为绝对路径。 |
| 缺少 `lib/index.mjs` | 链接插件前在插件目录运行 `pnpm build`。不支持直接从 GitHub 安装未构建的源码。 |
| 机器人名称检测失败 | 设置准确的 `botName`，或用 `groupPolicy: disabled` 只启用私聊。 |
| 消费者始终未就绪 | 查看本地 dsh 日志中的 CLI 配置、事件订阅、权限或网络错误。检查 `lark-cli event schema im.message.receive_v1 --json`，并参考[安装指南](setup.zh-CN.md)。 |
| `/help` 没有回复 | 检查应用可用范围、机器人是否在群中、当前应用下的发送者 ID、聊天白名单以及是否为文本消息。群聊中还需把机器人提及放在开头，并检查 `groupPolicy`。 |
| 私聊正常，群聊不响应 | 开通接收机器人提及的权限，将机器人加入允许的群，并使用准确的显示名。 |
| 任务一直等待，没有回答 | 使用 `/status`，再到 dsh Web UI 查看是否正在等待工具审批或遇到模型错误。飞书中不能批准待处理工具。 |
| 回复繁忙或容量不足 | 等待任务完成，用 `/stop` 丢弃当前聊天的排队任务，或用 `/new` 释放其会话。确认宿主资源后再提高限制。 |
| 回答被截断 | 在飞书消息限制范围内提高 `maxReplyChars`，或到 dsh 会话查看完整回答。 |
| 回答作为单独消息发送 | 回复原消息失败后，发送端退回到聊天中发送消息。失败原因请查看本地日志。 |
| 回答无法送达 | 检查应用发送权限以及是否仍在群中。投递失败会记录在本地；插件没有持久化发送队列。 |
| 重启后重复执行任务 | 事件去重记录有容量上限，且仅保存在内存中。检查是否运行多个桥接实例，重新发送任务前先查看会话。 |

## 查看事件消费者

```sh
lark-cli event status --json
```

此只读命令显示本地消费者。多个工具可能共享 CLI 事件守护进程，停止之前请确认进程归属。正常停止对应 dsh 实例，让插件完成取消订阅。避免强杀消费者，因为 CLI 可能需要删除服务端订阅。

## 不连接飞书，先检查配置

```sh
dsh --profile web --dump-config
```

找到 `dsh-lark` 层和 `lark` 行，确认最终 `config`，尤其留意 home 级或启动参数中的 patch 是否也修改该行。此命令只合成配置，不会建立飞书连接或验证工具权限。

如仍有问题，请提交[缺陷报告](https://github.com/ChengqianHuang/dsh-lark/issues/new?template=bug_report.yml)，附上最小脱敏配置和复现步骤。安全问题请遵循[安全报告规则](../SECURITY.zh-CN.md)。
